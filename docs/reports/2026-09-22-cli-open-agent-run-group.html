CLI Open Agent Group Selection

Implementation and verification in progress.

This report will be finalized after regression testing and independent code review. No completion or manual UI acceptance is claimed by this draft.

Requested behavior

Add optional run_group_id to cli_open_agent, so a caller can choose an existing tab group when opening a new CLI pane. Existing calls that omit the parameter retain their selection rules. The parameter applies to fresh panes and new panes that resume a conversation.

{
  "agent": "codex",
  "name": "reviewer",
  "task": "Review the requested change and report the findings.",
  "run_group_id": "<existing group ID in the target workspace>"
}

Read a saved group ID from cli_list_sessions rows. The example uses a placeholder; it is not a group that this change creates.

Compatibility contract

InputExpected behavior
Omitted or nullPreserve existing parent inheritance, saved-session fallback, and standalone selection behavior.
""Explicitly use the manual, ungrouped tab.
Existing group IDUse that group in the target workspace, overriding inherited or saved group selection.
Unknown or other-workspace IDReject before creating the pane, its PTY, or its persistent pane record.
pane_id plus an explicit groupReject with guidance to use cli_place_pane; reopening an existing pane must not silently move it.
session_id plus an explicit groupResume into a new pane in the selected group while preserving the existing parent-lineage rules.

      各 CLI 的帳號切換能力

      「現況」是程式目前宣告的能力；「計畫交付」是審閱中提案，尚未實作也未實機驗證。表格由 registry 的 15 個 CLI 產生。

      CLI帳號槽（現況）切換方式（現況）接續對話（現況）計畫交付

      共用規則（提案）

      • 預設「通知我」。自動切換需主動開啟；任一步失敗即通知並停止該輪，不改試下一個帳號。
      • 同一 CLI 在 5 小時滾動窗口內最多自動切換 3 次，兩次至少間隔 10 分鐘；等待安全閒置不計次。
      • 手動選擇的切換與手動切回不消耗自動次數；10 分鐘間隔與 5 小時窗口在原型中只是文案示意。
      • 不自動切回原帳號。原帳號只顯示「預計恢復」，實際切回由使用者按鈕啟動，走同一條切換流程。
      • 需要重啟的 CLI 預設等到所有受影響 pane 安全閒置再停止；忙碌、等待權限、有未送出輸入的 pane 不會被自動停止。此預設仍在審閱中。
      • 「帳號已切換」「對話已接續」「額度已驗證」是三件事，分開顯示；沒有可驗證的讀數就標為未確認。
      • Aider 與 MiniMax Code 沒有原生對話接續：更動憑證前先要求確認「保留原視窗並另開對話」；自動模式停止並通知。結果只算部分完成，不會顯示為對話已接續。

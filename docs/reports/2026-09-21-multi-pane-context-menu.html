Pane and project context menus

21 September 2026 · Local working tree · Implementation and verification

Make resource reclamation and notification control available for selected panes, group actions clearly, and improve the readability of destructive actions in the project menu.

Initial and follow-up automated checks passed. Initial full validation and the viewport correction's targeted tests, renderer type check, application build, and independent review are recorded separately below. Manual desktop acceptance has not been performed.

Problem and change

The multi-selection branch of the context menu contained Interrupt, Rebuild, Minimize, Restore, and Remove. Reclaim was available for individual panes and project-wide use, but the selection menu did not expose it.

The change adds Reclaim selected and a notification action that applies one consistent state to the whole selection. Existing separators group process actions, visibility/resource actions, notifications, and removal. The detached context menu also uses the app's font instead of falling back to a browser serif font.

The longer menu is limited to the window height with a small margin and scrolls when necessary. Existing menu positioning continues to keep it within the visible window.

The project overflow menu's “Close workspace and its panes” row inherited a solid red background from the shared button.danger rule, while .ws-more-opt.danger changed only its text color. The two rules produced the reported red-on-red text and icon.

The scoped correction uses a transparent default background, the theme's subtle danger background on hover or focus, bright danger text and icons, and an inset keyboard focus outline. The menu uses the existing theme font, line-height, shadow, and border tokens with light inset spacing. Its width, action handlers, and close confirmations stay unchanged.

Scope and protections

  • Reclaim uses the existing manual-reclaim eligibility rules. Protected panes include running panes, the focused pane, panes waiting for an answer, panes holding unsent text, and panes without a resumable session.
  • Both new actions operate on the selected pane IDs. Other panes and unselected descendants are outside the action.
  • A separate Start/Resume button is unnecessary because Restore selected already opens placeholder panes.
  • No new backend command, dependency, or persistence format is required. Existing unrelated worktree changes are preserved.

Follow-up code inspection and viewport correction

The fresh inspection found no regression in selection scope, reclaim protections, notification state, or the original action handlers. It did find an existing project-menu positioning issue: the overflow menu always opened below its trigger and had no viewport height cap or scrolling, so its final rows could be clipped near the bottom of a short window.

Code inspection findings

Selection and reclaim guardsActions retain a snapshot of the selected live pane IDs. Reclaim uses the existing eligibility checks and rechecks each pane before acting; unselected panes and protected sessions stay outside the action.
Notifications and persistenceA mixed selection receives one desired muted state; an entirely muted selection is unmuted. Each changed pane is persisted under its own workspace, with one view synchronization for the batch.

Viewport correctionThe project menu measures its rendered height after opening, preserves normal placement below the trigger, and clamps its position inside an 8 px window margin. Its height is capped at 100vh - 16px; internal menu scrolling keeps it open, while outside scrolling dismisses it. An opening-identity check ignores stale close/reopen measurements. Its existing adjacent-menu stacking level keeps it above the status bar.

Manual desktop acceptance

Status: not performed. Repository instructions prohibit UI automation and reserve desktop testing for the user. The following checks remain explicit manual acceptance items:

  1. Select multiple panes and open their context menu. Verify the action groups, readable app font, and labels in English and Traditional Chinese. In a short window, scroll the menu and confirm that the final Remove action remains reachable.
  2. Select eligible and protected panes together. Reclaim the selection; only eligible selected panes should become placeholders. Confirm that an unselected pane and unselected descendants remain intact.
  3. Select only protected panes. Verify that Reclaim selected remains visible and disabled.
  4. Restore selected placeholders and confirm that their expected CLI sessions resume.
  5. Select muted and unmuted panes together. Mute selected notifications should mute all of them; reopening the menu should offer Unmute selected notifications, which restores notifications for the selection.
  6. Confirm that single-pane menus and the existing Interrupt, Rebuild, Minimize, Restore, and Remove workflows behave as before.
  7. Open the project overflow menu in light and dark themes. Check that “Close workspace and its panes” and its icon are readable at rest, on hover, and when focused; check that the existing confirmation still appears before closing. Open it near the bottom of a short window and confirm that all rows remain reachable.
